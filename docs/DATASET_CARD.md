# Dataset card: Waze user churn (synthetic)

## Identity and provenance

- **Dataset name:** Waze user churn dataset (synthetic).
- **Source owner:** Created by Waze in collaboration with Google for churn
  analysis training material; distributed publicly on Kaggle.
- **Retrieval:** Downloaded from Kaggle for an earlier course project
  (RCEL 506) and reused here. Local copy:
  `data/local/waze_dataset.csv`.
- **License or access agreement:** **To be confirmed** from the Kaggle dataset
  page. Until then the CSV is not committed; only a constructed fixture is.
- **Immutable version:** SHA-256
  `958330c5395239d55c4263e6603b60c8c673b28bbfd17ff4477a74c1449d228d`
  (14,999 rows, 13 columns). The adapter refuses any file with a different
  checksum.

**To reproduce:** download the CSV from the Kaggle page, save it as
`data/local/waze_dataset.csv`, and run
`uv run pytest tests/test_waze_data.py`. The checksum test confirms you have
the same version.

## Observation and sampling

- **One row** is one Waze app user.
- **Population:** synthetic users generated to resemble Waze's user base. The
  sampling process and generator are not documented, so the rows should be
  treated as a convenience sample of a simulated population.
- **Dependence:** users are independent rows; there are no repeated
  measurements, households, or time series.
- **Time boundary:** one month of activity plus lifetime totals. The calendar
  period is not given.

## Schema and measurement

| Column | Meaning | Window | Notes |
| --- | --- | --- | --- |
| `ID` | Row identifier | — | Arbitrary; not a personal identifier |
| `label` | `retained` or `churned` | Observed month | **Target.** 700 rows (4.7%) missing → dropped |
| `sessions` | Times the app was opened | Month | |
| `drives` | Drives of at least 1 km | Month | Never exceeds `sessions` |
| `total_sessions` | Estimated sessions since onboarding | Lifetime | 18 labeled rows are below `sessions` (impossible), kept and flagged |
| `n_days_after_onboarding` | Days since sign-up | Lifetime | 4–3,500 |
| `total_navigations_fav1` | Navigations to favorite place 1 | Lifetime | |
| `total_navigations_fav2` | Navigations to favorite place 2 | Lifetime | |
| `driven_km_drives` | Kilometers driven | Month | Implied speed exceeds 200 km/h for 3,370 rows |
| `duration_minutes_drives` | Minutes driven | Month | See above |
| `activity_days` | Days the app was opened | Month | 0–31 |
| `driving_days` | Days with at least one drive | Month | Never exceeds `activity_days` |
| `device` | `iPhone` or `Android` | — | Encoded as `is_iphone` |

Window meanings follow the dataset's published data dictionary.

**Leakage and timing risk.** The month-level columns cover the same month in
which churn is recorded. A user who leaves mid-month shows both churn and
reduced activity, so the features partly reflect the outcome. No column is a
direct copy of the label, but results must be read as "detecting
disengagement in progress", not "predicting churn in advance".

**Derived fields.** `churned` = 1 if `label == "churned"`; `is_iphone` = 1 if
`device == "iPhone"`.

## Validation at the boundary

`dsm_project.data.waze.validate_waze_frame` rejects missing columns,
duplicate or missing IDs, non-numeric, non-finite, or negative usage values,
unknown labels or devices, day counts above 31, `driving_days >
activity_days`, and `drives > sessions`. The real file passes all checks.

## Data access and privacy

- **Committed:** loader and validation code, `configs/waze.toml` (with the
  checksum), and `data/fixtures/waze_fixture.csv`. The fixture is 120 rows
  generated by `scripts/build_waze_fixture.py`, not sampled from the real
  data, so it is safe to publish regardless of the license.
- **Local only:** the real CSV in `data/local/` (ignored by git).
- **CI:** tests and notebooks that need the real file skip themselves when it
  is absent; the fixture exercises the same code path.
- **Privacy:** the data are synthetic and contain no personal information.

## Representativeness and limitations

- **Synthetic.** Patterns may reflect the generator rather than real users.
- **Missing labels.** 700 users lack a label. Their usage and device mix match
  labeled users, so dropping them is unlikely to bias the sample, but this
  cannot be verified for unmeasured traits.
- **Implausible values.** About a quarter of rows imply average driving
  speeds above 200 km/h, and 18 rows have impossible lifetime totals. Rows are
  kept, and these columns are treated as noisy.
- **No time order.** One snapshot per user, so early prediction and drift
  over time cannot be studied.
- **Class balance.** 17.7% of labeled users churned.
